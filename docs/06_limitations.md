# 한계

[프로젝트 개요](../README.md) · [메인 실험](02_main_q0_vs_q17.md) · [분석 1](03_analysis1_q8.md)

- **길이를 통제하지 않았다.** 각 방법이 자연스럽게 만든 길이에서 비교했다. Naive는 평균 길이가 비슷했지만 119문서 중 107문서에서 Q0와 Q17의 보존율이 5%p 넘게 달랐다. 같은 길이에서 관련 정보를 고르는 능력만 분리한 결과가 아니다.
- **출력 형식이 함께 바뀌었다.** 가설 목록을 받으면 생성형 압축기가 원문 단위 번호와 본문을 옮겨 쓰는 경향이 생겼고(Naive 111/119문서), 일부 문서는 4,096토큰 생성 상한에 도달했다.
- **다중 비교를 보정하지 않았다.** 신뢰구간은 네 방법 비교를 보정하지 않은 탐색적 범위다. 보정하면 Naive의 개선도 경계선 수준이다.
- **한 번의 실행, 한 가지 배정.** greedy 디코딩으로 한 번 실행했고, Q8의 가설 배정은 seed 42의 한 가지뿐이다.
- **일반화 범위.** 비밀유지계약서(NDA), 고정 가설 17개, 압축·판단 모델 각 1개의 결과다. 다른 종류의 문서나 더 큰 모델에 바로 일반화할 수 없다.
- **비용.** 토큰을 줄여도 압축 자체의 연산 비용이 커서, 네 압축 조건의 전체 처리 시간(Q0 7.27시간, Q17 8.02시간)이 원문 판단(약 1.08시간)보다 길었다.
- **정답 데이터의 약점.** Contradiction은 2,023문항 중 216개로 적고, 원문 판단에서도 Recall이 18.06%로 낮다. 이 라벨의 결과는 변동이 크다.

분석 2·3이 끝나면 위치 편향과 근거 손실이 결과를 얼마나 설명하는지에 따라 이 목록을 보완한다.
