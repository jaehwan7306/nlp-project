## 질문

모델이 실제로 읽는 입력에서 판단 근거가 앞·중간·뒤 중 어디에 놓이느냐에 따라 정답률이 달라지는가? 선행연구는 관련 정보를 긴 입력의 여러 위치에 옮겨 성능 변화를 시험했다([Liu et al., 2024](https://aclanthology.org/2024.tacl-1.9/)). 이 분석은 ContractNLI의 실제 입력 순서에서 근거 위치별 판단 성능을 관찰한다.

## 입력 구조

| 모델이 읽는 단계 | 입력 순서 |
|---|---|
| 압축 | 지시 → 제공 가설 목록(Q8·Q17) → 번호가 붙은 계약서 원문 |
| 판단 | 분류 지시 → 원문 또는 압축 문맥 → 현재 평가할 가설 1개 |

Gold Evidence는 어떤 가설의 판단 근거가 되는지 표시한 **원문의 문자 범위**다. 가설별 근거 ID를 문서의 `spans`에 연결하면 범위를 찾을 수 있다. 프롬프트 지시와 가설이 앞뒤에 붙으므로, 전체 입력에서 같은 문장의 토큰 위치는 계약서 안에서의 위치와 다를 수 있다. [공식 데이터 형식](https://stanfordnlp.github.io/contract-nli/) · [판단 프롬프트](../contract_experiment/prompts.py)

## 방법

1. 원문이 그대로 들어가는 Original 판단 입력부터 재구성해 근거의 위치를 확인한다. 계약서 구간 안의 위치와, 지시·가설을 포함한 전체 입력 안의 위치를 각각 기록한다.
2. 근거가 여러 곳에 흩어진 문항의 처리와 앞·중간·뒤 구간 경계를 먼저 정한다. 근거가 없는 NotMentioned 문항은 따로 집계한다.
3. 구간별 문항 수와 정답률을 비교한다. 계약서 길이와 가설·라벨 분포의 차이를 함께 보고한다.

필요한 파일과 연결 방법은 [재현 가이드 · 팀 분석 파일](reproducibility.md#team-data)에 있다. 전체 입력의 토큰 위치는 판단 프롬프트와 고정 Qwen3 토크나이저([model_revisions.json](model_revisions.json))로 계산한다.
