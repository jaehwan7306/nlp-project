# 현재까지의 실험 결과

[프로젝트 개요](../README.md) · [공개 결과 파일·그림](../results/README.md) · [재현 및 실행 명령](REPRODUCIBILITY.md)

정리일: 2026-11-16. 질문 없는 Main과 고정 17개 가설 목록을 제공하는 추가 분석 1을 완료했다. 아래 수치는 저장된 Test 결과를 확인해 정리한 값이다. 길이를 제약하는 추가 분석 2와 Gold Evidence 오류 분석 3은 아직 실행하지 않았다.

## 데이터와 실행 범위

공식 ContractNLI는 Train 423·Dev 61·Test 123문서다. Train은 데이터 감사에만 사용하고 모델 학습·판단에 쓰지 않았다. Dev는 기술 점검과 규칙 동결에 사용했으며 정확도로 설정을 선택하지 않았다.

사람이 중복 후보를 검토한 현재 실행의 Test 제외 결정은 다음과 같다. 라벨은 수정하지 않았고 제외 ID를 코드에 하드코딩하지 않았다.

| 후보 | 사람의 결정 | 적용 결과 |
|---|---|---|
| 52 / 97 | 원문 완전 중복으로 `duplicate` | 52 유지, 97 제외 |
| 395 / 444 | 줄바꿈·서명 등 차이를 검토하고 `duplicate` | 395 유지, 444 제외 |
| 537 / 539 | 라벨 불일치로 `exclude_both` | 두 문서 모두 제외 |

최종 Test는 **119문서 × 17가설 = 2,023문항**이다.

| 실행 | 새 압축 | 새 판단 | 재사용 |
|---|---:|---:|---|
| Main | 476회 | 10,115개 판단 기록 | 이전 Test 모델 출력 재사용 없음 |
| 추가 분석 1 | 476회 | 8,092회 | Main Original 2,023건, 질문 없는 결과는 비교 기준으로 참조 |

Main 판단 기록 중 기존 추출형·일반 압축 실패 문서의 17문항은 모델 판단을 생략하고 오답으로 기록했다. 저장된 기록 수와 실제 모델 호출 수를 구분한다. 추가 분석 1은 새 모델 판단 8,092회가 모두 완료됐다.

실행 모델은 Qwen2.5-7B-Instruct / Qwen3-8B이며 NF4 4bit·bfloat16·명시적 greedy를 사용했다. 실제 환경은 Python 3.11.9, PyTorch 2.8.0+cu128, NVIDIA GeForce RTX 5070이었다. 고정 리비전과 재현 절차는 [실행 안내](REPRODUCIBILITY.md)에 있다.

## Main: 질문 없는 압축

| 조건 | Accuracy | Macro-F1 | 평균 토큰 보존율 | 중앙 토큰 보존율 |
|---|---:|---:|---:|---:|
| Original | 63.72% | 0.5255 | 100.00% | 100.00% |
| 생성형·일반 / Naive | 61.05% | 0.5101 | 62.77% | 66.26% |
| 생성형·보존 우선 / Contextualized | 61.34% | 0.5119 | 46.15% | 40.90% |
| 추출형·일반 | 61.84% | 0.5000 | 83.96% | 90.60% |
| 추출형·보존 우선 | 62.14% | 0.4978 | 76.91% | 79.89% |

보존율은 **판단 문맥의 Qwen3 토큰 수 / 원문 토큰 수**다. 평균은 문서별 비율의 산술평균이며 전체 토큰 합의 비율과 다르다. 추출형·일반의 길이는 압축 실패 1문서를 제외한 118문서 기준이고, 나머지는 119문서다. 성능 분모는 실패를 포함한 2,023문항으로 동일하다.

- 압축 네 조건의 정확도는 Original보다 약 1.58~2.67%p 낮았다.
- 추출형은 원문을 많이 남겼다. 높은 정확도를 압축 방식만의 장점으로 해석하기 어려운 이유다.
- 보존 우선 생성형은 일반 생성형보다 짧았지만 비슷한 정확도를 보였다. 같은 길이를 맞춘 비교는 아니다.

## 추가 분석 1: 고정 17가설 목록 제공

압축 user 입력에 17개 가설과 공통 안내를 함께 넣고, 문서·방법별 한 번 압축했다. 판단은 기존과 같이 문맥과 가설 한 개씩 입력했다. 모델·정밀도·기본 지시·greedy·안전 상한·전체 문맥 OOM 정책을 유지했고 Gold Label·Gold Evidence와 목표 길이는 압축에 제공하지 않았다.

Q0는 질문 없는 Main, Q17은 질문 목록 제공 실행이다. Original 결과는 Main과 동일한 기록을 재사용했다.

| 방법 | Q17 Accuracy | Q17 Macro-F1 | Q0 대비 정확도 차이 | 차이의 95% CI (%p) |
|---|---:|---:|---:|---|
| Naive | **63.67%** | **0.5450** | **+2.62%p** | [0.59, 4.75] |
| Contextualized | 60.80% | 0.5089 | −0.54%p | [−2.67, 1.58] |
| 추출형·일반 | 60.41% | 0.4958 | −1.43%p | [−3.51, 0.74] |
| 추출형·보존 우선 | 59.96% | 0.4891 | −2.17%p | [−4.10, −0.30] |

| 방법 | 평균 보존율 Q0 → Q17 | 중앙 보존율 Q0 → Q17 |
|---|---:|---:|
| Naive | 62.77% → 62.51% | 66.26% → 61.23% |
| Contextualized | 46.15% → 50.77% | 40.90% → 50.34% |
| 추출형·일반 | 83.96% → 48.52% | 90.60% → 46.98% |
| 추출형·보존 우선 | 76.91% → 49.37% | 79.89% → 49.77% |

Naive는 정답이 1,235개에서 1,288개로 53개 늘었다. Entailment +43개, Contradiction +11개, NotMentioned −1개였다. 정확도는 Original의 1,289개 정답과 한 개 차이지만, Original 정답 146개를 놓치고 기존 오답 145개를 새로 맞힌 결과다. Original 정답 유지율은 88.67%이므로 두 조건의 판단이 같다고 볼 수 없다.

Contextualized는 Entailment 정답이 62개 늘었지만 NotMentioned 정답이 72개 줄어 전체 이득이 없었다. 추출형은 남긴 분량과 Entailment 정답이 함께 감소했고 NotMentioned 예측이 늘었다. 실제 근거가 삭제됐는지와 판단 모델의 오류를 구분하려면 이후 근거 대조가 필요하다.

CI는 같은 문서의 17문항을 함께 추출하는 paired 문서 부트스트랩 10,000회·seed 42·percentile 95% 방식이다. Macro-F1도 매 반복 재계산한다. Naive의 정확도·Macro-F1 개선 CI는 0을 포함하지 않는다. 추출형·보존 우선은 정확도 차이 CI가 음수지만 Macro-F1 차이 CI는 0을 포함한다. 다중 비교를 보정하지 않은 탐색적 결과다.

## 출력 문제와 해석 범위

**생성형 출력 방식이 크게 달라졌다.** 원래 프롬프트는 원문 단위 ID를 출력하지 않도록 했지만 질문 제공 후 번호와 원문 본문을 남긴 사례가 많았다.

| 생성형 조건 | 줄 시작 `[숫자]` 표시가 있는 Q0 문서 | Q17 문서 |
|---|---:|---:|
| Naive | 1/119 | 111/119 |
| Contextualized | 1/119 | 101/119 |

번호 뒤 텍스트를 해당 원문 단위와 공백 정규화 후 대조했을 때, Q17 Naive 104문서·Contextualized 89문서에서 완전히 같은 단위가 한 개 이상 확인됐다. 이 사후 점검은 의미적 충실도나 Gold Evidence 보존율 지표가 아니다. 번호 없이 복사한 텍스트도 잡지 못한다.

또한 Q17에서는 다음을 기록했다.

- 생성형 두 조건에서 각각 3문서가 4,096 생성 토큰 안전 상한에 도달했다.
- 추출형 두 조건 모두 `test:90`, `test:336`, `test:455`에서 빈 목록 `[]`을 반환했다. 정상 형식의 빈 선택이며 각 조건에서 51문항을 그대로 평가했다.
- 압축·판단 파싱 실패는 0건이었다. 형식 파싱 성공이 본문의 의미 품질을 보장하지 않는다.
- Naive 13문서·Contextualized 5문서는 실제 보존율이 100%를 넘었다.

**평균 길이가 비슷해도 문서별 길이는 통제되지 않았다.** Naive의 119문서 중 107문서는 Q0와 Q17의 보존율 차이가 5%p보다 컸다. 그러므로 현재 관측은 출력 길이·형식·선택 방식의 변화를 포함한 질문 목록 제공의 전체 효과다.

## 비용과 현재 결론

네 압축 조건의 저장된 압축·판단 시간 합은 Main 약 **7.27시간**, Q17 약 **8.02시간**이었다. Q17의 새 비용에는 재사용 Original을 넣지 않았다. 모델 로드·Dev preflight·중단·대기 시간은 제외한 관측이며 다른 실행 시점의 속도를 통제한 벤치마크는 아니다.

현재 결과는 다음처럼 요약할 수 있다.

> 고정 17개 가설 목록 제공은 Naive의 판단 성능을 개선했지만, 다른 방법에서 일관된 개선은 나타나지 않았다. 추출형에서는 선택 분량과 Entailment Recall이 함께 감소했다. 질문 제공은 생성형의 원문 번호·본문 보존 등 출력 방식도 바꿨으므로, 같은 길이에서 관련 정보 선택 능력만 분리한 결과로 해석하지 않는다.

다음 비교는 계획한 추가 분석 2의 길이 제약, 추가 분석 3의 Gold Evidence 대조다. 현재 결과를 사후에 유리한 출력으로 바꾸지 않고 출력 이상도 함께 보존한다.

## 결과 출처와 재현 자료

성능·길이·시간 CSV, 집계 JSON, 상세 분석과 PNG/PDF 그림은 [공개 결과 폴더](../results/README.md)에서 확인할 수 있다. CSV는 원본 바이트를 유지했고 JSON의 로컬 컴퓨터 경로와 보고서 링크는 공개 구조에 맞게 정리했다. 파일별 원본·공개본 SHA256과 변환 내역은 [manifest.json](../results/manifest.json)에 기록했다. 문항별 Gold·예측 CSV는 로컬 원본 run에 보관한다.

로컬 원본 결과 위치는 다음과 같다. 데이터·모델 캐시·전체 원시 run은 팀에서 별도로 보관한다.

| 위치 | 내용 |
|---|---|
| `runs/test_memory_safe/results/metrics.csv` | Main 성능과 길이 |
| `runs/questions17/results/question_effects.csv` | Q17−Q0 성능·CI·길이·실패·정답 전환 |
| `runs/questions17/results/metrics.csv` | Q17 성능과 재사용 Original |
| `runs/questions17/results/question_label_effects.csv` | 라벨별 변화 |
| `runs/questions17/results/question_times.csv` | 시간과 재사용 비용 구분 |
| 각 run의 `contexts.jsonl`, `predictions.jsonl` | 원본 압축·판단 출력 |
| 각 run의 `prompts.json`, `models.json`, `environment.json`, `manifest.json` | 실제 지시·버전·환경·해시 |

평가에 사용한 공개 구현은 [Main/OOM 실행](https://github.com/jaehwan7306/nlp-project/commit/7c4b61b4cad5f8722fb12cb601be6d266db0d879)과 [Q17 추가 분석](https://github.com/jaehwan7306/nlp-project/commit/bfe6d21defba641ebfea59e5560c70d101b99116)이며, 실제 실행의 정체성은 보관된 run 스냅샷·소스 해시로 확인한다. 고정 모델 리비전은 [model_revisions.json](model_revisions.json)에 있다.

이번 문서 정리는 저장 결과의 읽기 전용 확인으로 진행했다. 모델 가중치를 로드하거나 새 실험을 실행하지 않았다.
