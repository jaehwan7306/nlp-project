# 의사결정 기록

이 문서는 구현의 선택 이유를 보관한다. 관측하지 않은 성능·충실도 개선을 결과처럼 기록하지 않는다. Dev에서 바꾸는 수치는 근거와 새 run ID를 덧붙이고 Test 전에 동결한다. 과거 실험의 결정·제외 ID·결과를 가져오지 않았다.

## D001 · 2026-11-12 · 메인 범위

- 문제: 질문·길이·압축 방식의 변경을 한꺼번에 해석하기 어렵다.
- 결정: Original과 생성형/추출형 × 일반/보존 우선의 5조건만 구현한다. 질문과 길이 목표는 압축 프롬프트에 제공하지 않는다. 추가 분석은 구현하지 않는다.
- 통제: 네 조건은 같은 Qwen2.5 모델·정밀도·디코딩을 사용한다. 같은 방식에서는 우선순위 문장 하나만 다르다. Qwen3 판단 설정은 모든 조건에 공통이다.
- 한계: 자연 출력 길이 차이는 남으며 같은 길이에서의 방법 우열로 해석하지 않는다.

## D002 · 2026-11-12 · 원문 단위와 조합

- 문제: 공식 spans가 원문의 모든 비공백 내용을 포함하는지는 새 데이터에서 확인해야 한다.
- 결정: 공식 전체 span을 그대로 유지하고 비공백 틈은 원문 문자 범위를 그대로 별도 단위로 추가한다. 겹치거나 범위를 벗어난 span은 실패로 처리한다. 짧은 단위·내용이 있는 틈을 audit 산출물로 보고한다.
- 통제: 네 압축 조건 모두 같은 번호가 붙은 단위를 받는다. Gold Evidence 선택 여부는 주지 않는다.
- 조합: 선택 단위를 원문 위치 순서로 정렬하고 두 줄바꿈으로 연결한다. 단위 내부는 그대로 유지한다. ID와 구분 표시는 판단 문맥에서 제거한다.
- 한계: 별도 단위인 예외를 선택하지 않으면 의미가 달라질 수 있다. 공식 단위가 의미적 완결성을 보장한다고 주장하지 않는다.

## D003 · 2026-11-12 · 공유 정밀도와 모델 실행

- 결정: 두 모델 모두 4bit NF4, double quantization, bf16 compute, SDPA, greedy를 초기 기본값으로 사용한다. Qwen3은 `enable_thinking=False`다. 한 번에 한 모델만 명시적인 CUDA 장치에 올린다.
- 이유: 12GB 환경의 실행 가능성을 고려하고, CPU 오프로딩이나 정밀도를 조건별로 자동 변경하지 않기 위해서다. 전체 입력 로짓 대신 마지막 위치 로짓만 계산하도록 `logits_to_keep=1`을 사용한다.
- 변경: bf16 미지원이면 Dev 전에 두 모델에 공통으로 float16을 지정한다. Dev 기술 점검 후 고정한다.
- 검증 범위: 모델 리비전은 로컬 `lock-models` 명령으로 실제 SHA를 고정한다. 에이전트는 가중치·실제 GPU 실행을 검증하지 않았다.

## D004 · 2026-11-12 · 종료와 안전 상한

- 결정: 네 압축 조건 모두 `max_new_tokens=4096`, 판단은 `32`를 실행 안전 상한의 초기값으로 사용한다. 원문 길이·보존율과 연동하지 않는다. 최소 길이·재작성·후보 선택·자동 재생성은 제공하지 않는다.
- 이유: 길이 목표 없이 자연 종료하는 실험을 구현하면서 무한 출력에 대한 기술적 방어를 두기 위해서다. 추출형에도 같은 생성 상한을 적용한다.
- 기록: eos/stop_string/max_tokens, 상한 도달, 원본 출력과 생성 토큰 ID를 보관한다. 줄 시작 Human/User/Assistant 태그를 정지 문자열로 사용한다.
- 변경: 안전 상한·정지 문자열이 부적절하면 Dev의 길이·형식 로그를 근거로 새 설정과 새 Dev run을 만든다. Test 결과로 고르지 않는다.

## D005 · 2026-11-12 · 파싱 실패의 집계

- 추출형: JSON 정수 배열 또는 배열 하나를 감싼 완전한 JSON 코드 블록만 허용한다. 설명·객체 포장·문자열 ID·bool·없는 ID는 실패다. 중복 ID는 한 번 쓰고 기록한다. `[]`는 정상 빈 선택이다.
- 생성형: 정지 문자열 앞의 본문을 사용한다. 빈 본문도 빈 문맥으로 평가하고 기록한다. 원문 대체·내용 보완은 하지 않는다.
- 판단: 공백·대소문자·표기 변형을 정리해 라벨을 찾는다. 세 라벨 중 구분 가능한 라벨 종류가 하나일 때만 채택한다. 서로 다른 라벨 둘 이상 또는 라벨 없음은 실패다. 재시도하지 않는다.
- 집계: 압축 실패는 해당 17문항을 null 예측의 오답으로 남긴다. 판단 파싱 실패도 오답이다. 실패 문항을 제거하지 않는다. 압축 실패 길이는 결측이며 0으로 취급하지 않는다.
- 구분: OOM·입력 한도 초과 등의 실행 오류는 그 항목을 완료로 저장하지 않고 중단한다. 동일 설정으로 재개할 수 있다.

## D006 · 2026-11-12 · 새 중복 검토

- 후보 생성: NFKC·casefold·공백 정규화 사본을 사용한다. 원문은 변경하지 않는다. 연속 5단어 shingle 집합의 Jaccard 0.95 이상을 초기 유사 후보로 보고하고 완전 중복도 포함한다.
- 사람 결정: `duplicate`/`distinct`와 근거를 기록한다. Train 교차 후보는 보고만 한다. Dev/Test 관련 후보의 미검토 행이 있으면 prepare를 중단한다. 원문 완전 중복도 이번 검토에서 확인한다.
- 그룹 규칙: 같은 내용·같은 라벨이면 Test 우선, 같은 split에서 작은 ID 유지. 같은 내용·라벨 충돌 그룹은 전체 제외한다. Evidence 텍스트 차이는 라벨 충돌과 구분한다.
- 한계: 이 후보 생성 방식이 모든 중복을 찾아낸다고 보장하지 않는다. 후보 점수만으로 제외하지 않는다.

## D007 · 2026-11-12 · 단계 동결과 재개

- 결정: prepared 데이터·설정·모델 SHA·소스·프롬프트를 run에 저장하고 해시를 검사한다. 전체 Dev의 기술 점검 후 protocol을 동결한다. 소규모 preflight는 동결에 사용하지 않는다.
- Test: 한 protocol에 Test run 하나를 연결하고 같은 폴더에서 재개한다. Test의 소스·설정·환경·GPU·템플릿은 동결한 Dev와 맞춘다. 정확도나 사람 충실도 점수로 자동 통과시키는 게이트는 없다.
- 재개: 완료한 성공·형식 실패 출력은 그대로 두고 누락 작업만 실행한다. OS 파일 잠금과 행별 fsync를 사용한다. 불완전한 마지막 JSONL 행은 백업 후 복구한다. 중간 손상·중복 키는 오류다.
- 환경: 직접 의존성을 고정하고 실제 전체 패키지 버전과 GPU를 기록한다. greedy와 seed는 다른 하드웨어의 비트 단위 일치를 보장하지 않는다.

## D008 · 2026-11-12 · 메인 집계

- 결정: Accuracy·Macro-F1·혼동행렬·클래스 Recall·Original 대비 차이·정답 유지율·실패율·길이·시간을 계산한다. 분류 실패는 Invalid 열로 두고 F1의 false negative에 반영한다.
- 길이: 최종 문맥의 Qwen3 토큰 수 / 원문 문맥의 Qwen3 토큰 수. 지시·가설·채팅 형식·선택 ID를 제외한다. 실패 길이 결측 수를 함께 보고한다.
- 통계: 같은 문서의 17문항을 함께 복원추출하는 paired cluster bootstrap, 10,000회, seed 42, percentile 95% CI. Macro-F1은 반복마다 재계산한다.
- 시간: 조건별 압축·판단 시간에 모델 로딩을 넣지 않고 로딩 시간을 별도 이벤트로 보관한다.
- Dev: 정확도 분석 CLI를 제공하지 않고 기술 진단만 제공한다. Test Original 단독 결과와 전체 결과는 별도 경로에 저장한다.
