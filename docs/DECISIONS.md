# 의사결정 기록

이 문서는 구현의 선택 이유를 보관한다. 관측하지 않은 성능·충실도 개선을 결과처럼 기록하지 않는다. Dev에서 바꾸는 수치는 근거와 새 run ID를 덧붙이고 Test 전에 동결한다. 과거 실험의 결정·제외 ID·결과를 가져오지 않았다.

## D001 · 2026-11-12 · 메인 범위

- 문제: 질문·길이·압축 방식의 변경을 한꺼번에 해석하기 어렵다.
- 결정: Original과 생성형/추출형 × 일반/보존 우선의 5조건만 구현한다. 질문과 길이 목표는 압축 프롬프트에 제공하지 않는다. 추가 분석은 구현하지 않는다.
- 통제: 네 조건은 같은 Qwen2.5 모델·정밀도·디코딩을 사용한다. 같은 방식에서는 우선순위 문장 하나만 다르다. Qwen3 판단 설정은 모든 조건에 공통이다.
- 한계: 자연 출력 길이 차이는 남으며 같은 길이에서의 방법 우열로 해석하지 않는다.

## D002 · 2026-11-12 · 원문 단위와 조합

- 문제: 공식 spans가 원문의 모든 비공백 내용을 포함하는지는 새 데이터에서 확인해야 한다.
- 결정: 공식 전체 span을 그대로 유지하고 비공백 틈은 원문 문자 범위를 그대로 별도 단위로 추가한다. 겹치거나 범위를 벗어난 span은 실패로 처리한다. 짧은 단위·내용이 있는 틈을 audit 산출물로 보고한다.
- 통제: 네 압축 조건 모두 같은 번호가 붙은 단위를 받는다. Gold Evidence 선택 여부는 주지 않는다.
- 조합: 선택 단위를 원문 위치 순서로 정렬하고 두 줄바꿈으로 연결한다. 단위 내부는 그대로 유지한다. ID와 구분 표시는 판단 문맥에서 제거한다.
- 한계: 별도 단위인 예외를 선택하지 않으면 의미가 달라질 수 있다. 공식 단위가 의미적 완결성을 보장한다고 주장하지 않는다.

## D003 · 2026-11-12 · 공유 정밀도와 모델 실행

- 결정: 두 모델 모두 4bit NF4, double quantization, bf16 compute, SDPA, greedy를 초기 기본값으로 사용한다. Qwen3은 `enable_thinking=False`다. 한 번에 한 모델만 명시적인 CUDA 장치에 올린다.
- 이유: 12GB 환경의 실행 가능성을 고려하고, CPU 오프로딩이나 정밀도를 조건별로 자동 변경하지 않기 위해서다. 전체 입력 로짓 대신 마지막 위치 로짓만 계산하도록 `logits_to_keep=1`을 사용한다.
- 변경: bf16 미지원이면 Dev 전에 두 모델에 공통으로 float16을 지정한다. Dev 기술 점검 후 고정한다.
- 검증 범위: 모델 리비전은 로컬 `lock-models` 명령으로 실제 SHA를 고정한다. 에이전트는 가중치·실제 GPU 실행을 검증하지 않았다.

## D004 · 2026-11-12 · 종료와 안전 상한

- 결정: 네 압축 조건 모두 `max_new_tokens=4096`, 판단은 `32`를 실행 안전 상한의 초기값으로 사용한다. 원문 길이·보존율과 연동하지 않는다. 최소 길이·재작성·후보 선택·자동 재생성은 제공하지 않는다.
- 이유: 길이 목표 없이 자연 종료하는 실험을 구현하면서 무한 출력에 대한 기술적 방어를 두기 위해서다. 추출형에도 같은 생성 상한을 적용한다.
- 기록: eos/stop_string/max_tokens, 상한 도달, 원본 출력과 생성 토큰 ID를 보관한다. 줄 시작 Human/User/Assistant 태그를 정지 문자열로 사용한다.
- 변경: 안전 상한·정지 문자열이 부적절하면 Dev의 길이·형식 로그를 근거로 새 설정과 새 Dev run을 만든다. Test 결과로 고르지 않는다.

## D005 · 2026-11-12 · 파싱 실패의 집계

- 추출형: JSON 정수 배열 또는 배열 하나를 감싼 완전한 JSON 코드 블록만 허용한다. 설명·객체 포장·문자열 ID·bool·없는 ID는 실패다. 중복 ID는 한 번 쓰고 기록한다. `[]`는 정상 빈 선택이다.
- 생성형: 정지 문자열 앞의 본문을 사용한다. 빈 본문도 빈 문맥으로 평가하고 기록한다. 원문 대체·내용 보완은 하지 않는다.
- 판단: 공백·대소문자·표기 변형을 정리해 라벨을 찾는다. 세 라벨 중 구분 가능한 라벨 종류가 하나일 때만 채택한다. 서로 다른 라벨 둘 이상 또는 라벨 없음은 실패다. 재시도하지 않는다.
- 집계: 압축 실패는 해당 17문항을 null 예측의 오답으로 남긴다. 판단 파싱 실패도 오답이다. 실패 문항을 제거하지 않는다. 압축 실패 길이는 결측이며 0으로 취급하지 않는다.
- 구분: OOM·입력 한도 초과 등의 실행 오류는 그 항목을 완료로 저장하지 않고 중단한다. 동일 설정으로 재개할 수 있다.

## D006 · 2026-11-12 · 새 중복 검토

현재 적용 규칙은 D010으로 수정했다. 아래는 최초 구현 당시의 결정 기록이다.

- 후보 생성: NFKC·casefold·공백 정규화 사본을 사용한다. 원문은 변경하지 않는다. 연속 5단어 shingle 집합의 Jaccard 0.95 이상을 초기 유사 후보로 보고하고 완전 중복도 포함한다.
- 사람 결정: `duplicate`/`distinct`와 근거를 기록한다. Train 교차 후보는 보고만 한다. Dev/Test 관련 후보의 미검토 행이 있으면 prepare를 중단한다. 원문 완전 중복도 이번 검토에서 확인한다.
- 그룹 규칙: 같은 내용·같은 라벨이면 Test 우선, 같은 split에서 작은 ID 유지. 같은 내용·라벨 충돌 그룹은 전체 제외한다. Evidence 텍스트 차이는 라벨 충돌과 구분한다.
- 한계: 이 후보 생성 방식이 모든 중복을 찾아낸다고 보장하지 않는다. 후보 점수만으로 제외하지 않는다.

## D007 · 2026-11-12 · 단계 동결과 재개

- 결정: prepared 데이터·설정·모델 SHA·소스·프롬프트를 run에 저장하고 해시를 검사한다. 전체 Dev의 기술 점검 후 protocol을 동결한다. 소규모 preflight는 동결에 사용하지 않는다.
- Test: 한 protocol에 Test run 하나를 연결하고 같은 폴더에서 재개한다. Test의 소스·설정·환경·GPU·템플릿은 동결한 Dev와 맞춘다. 정확도나 사람 충실도 점수로 자동 통과시키는 게이트는 없다.
- 재개: 완료한 성공·형식 실패 출력은 그대로 두고 누락 작업만 실행한다. OS 파일 잠금과 행별 fsync를 사용한다. 불완전한 마지막 JSONL 행은 백업 후 복구한다. 중간 손상·중복 키는 오류다.
- 환경: 직접 의존성을 고정하고 실제 전체 패키지 버전과 GPU를 기록한다. greedy와 seed는 다른 하드웨어의 비트 단위 일치를 보장하지 않는다.

## D008 · 2026-11-12 · 메인 집계

- 결정: Accuracy·Macro-F1·혼동행렬·클래스 Recall·Original 대비 차이·정답 유지율·실패율·길이·시간을 계산한다. 분류 실패는 Invalid 열로 두고 F1의 false negative에 반영한다.
- 길이: 최종 문맥의 Qwen3 토큰 수 / 원문 문맥의 Qwen3 토큰 수. 지시·가설·채팅 형식·선택 ID를 제외한다. 실패 길이 결측 수를 함께 보고한다.
- 통계: 같은 문서의 17문항을 함께 복원추출하는 paired cluster bootstrap, 10,000회, seed 42, percentile 95% CI. Macro-F1은 반복마다 재계산한다.
- 시간: 조건별 압축·판단 시간에 모델 로딩을 넣지 않고 로딩 시간을 별도 이벤트로 보관한다.
- Dev: 정확도 분석 CLI를 제공하지 않고 기술 진단만 제공한다. Test Original 단독 결과와 전체 결과는 별도 경로에 저장한다.

## D009 · 2026-11-12 · 중복 후보의 직접 비교 화면

- 문제: review.csv에는 점수·문서 ID·결정 칸만 있어 실제 어떤 문장이 다른지 바로 확인하기 어렵다.
- 결정: 외부 패키지·인터넷·모델 없이 열 수 있는 HTML 보고서를 추가한다. 변경된 원문 줄과 주변 문맥, 전체 원문, 서로 다른 라벨의 가설과 양쪽 Gold Evidence를 표시한다.
- 사용: 새 audit에서는 자동 생성하고 기존 audit에서는 `review-report` 명령으로 생성한다. CSV·audit.json·원문·제외 판단은 수정하지 않는다.
- 해석: 5단어 shingle Jaccard는 문자 일치율·의미 일치율이 아니다. 실제 원문을 확인해 같은 계약서인지 판단한다. 라벨을 임의로 고치지 않는다.
- 영향: 실험 조건·중복 후보 점수·제외 규칙·모델 입력은 바꾸지 않는다. 출력 HTML의 모든 원문·가설·근거를 이스케이프한다.
- 검증: 합성 문서 쌍으로 원문 diff, 라벨·근거 표시, HTML 이스케이프, 검토 파일 비변경을 확인한다.

## D010 · 2026-11-12 · 사람의 최종 제외 결정을 명시

- 사용자 요청: 같은 `duplicate` 입력으로 52/97은 하나 유지하고 537/539는 양쪽 제외되는 자동 처리를 원하지 않는다. 사람이 검토한 최종 제외 방식도 별도 값으로 선택해야 한다.
- 변경: `duplicate`는 한 문서 유지(Test 우선, 같은 split에서 작은 ID), `exclude_both`는 해당 두 문서 모두 제외, `distinct`는 이 쌍으로 추가 제외하지 않음이다. notes를 필수로 기록한다.
- 제거: 최종 제외 단계의 Gold 라벨 비교에 따른 자동 분기. 원본 라벨 차이와 Gold Evidence는 사람이 볼 비교 자료로 계속 표시한다. Gold의 정답성을 코드가 검수한다고 해석하지 않는다.
- 반영: 사용자 사례의 52/97은 `duplicate`, 537/539는 `exclude_both`를 직접 선택한다. 데이터 ID를 코드에 하드코딩하거나 기존 CSV를 자동 변환하지 않는다.
- 기록: exclusions.csv에 decision·관련 검토 행·사람의 notes를 남긴다. 겹치는 후보에서 유지 대상과 명시 제외 대상이 충돌하면 임의 해결하지 않는다.
- 이전 산출물: raw data/audit/review 파일은 보존한다. 이전 자동 정책으로 만든 prepared는 새 출력 폴더에 다시 준비해야 한다. 새 실행·동결에는 새 prepared를 사용한다.
- 변인통제: 압축·판단 프롬프트와 모델 설정은 바꾸지 않는다. 평가 대상 선택의 최종 권한을 사람의 명시적 결정으로 옮긴다.
- 검증: 라벨이 달라도 duplicate는 하나 유지하고, 라벨이 같아도 exclude_both는 둘 다 제외하는 합성 사례를 확인한다.

## D011 · 2026-11-14 · 추가 분석의 질문 정보를 17개 가설 목록으로 제공

- 사용자 결정: 추가 분석 1·2에서 질문 17개를 한꺼번에 제공하고 문서·압축방법별 한 번 압축한다. 메인은 기존 질문 없는 5조건으로 진행한다.
- 이전 구상: 가설 한 개마다 문맥을 별도로 생성해 질문 제공 조건의 압축을 문서당 17번 수행했다.
- 변경: 공식 17개 가설의 고정 목록을 제공하고, 방법별 문맥 하나를 17개 가설의 판단에 재사용한다. 네 방법의 목록·순서·삽입 형식을 동일하게 고정한다. Qwen3에는 기존처럼 문맥과 가설 한 개씩 제공한다.
- 이유: 질문 정보 제공 효과라는 프로젝트 목적을 유지하면서 압축 호출 수와 구현 복잡도를 줄이기 위해서다.
- 해석 범위: 개별 질문에 최적화된 압축 효과가 아니라, 평가할 가설 목록을 미리 아는 효과를 비교한다. 가설 목록이 모든 계약서에 고정되어 있다는 한계도 함께 명시한다.
- 통제: 가설은 검증 대상이며 사실로 가정하지 않는다. Gold Label·Gold Evidence는 압축에 제공하지 않는다. 기본 작업 지시·모델·정밀도·디코딩·출력 형식은 메인과 맞춘다. 추가 분석 2는 질문 유무에 같은 원문 기준 예산을 적용한다.
- 비용: N문서에서 추가 분석 1의 기본 새 압축은 4N회, 판단은 68N회다. 추가 분석 2는 목표 보존율 한 종류와 질문 유무 모두에서 압축 8N회, 판단 136N회다. 추가 분석 1의 질문 없는 비교 기준은 메인 결과를 재사용하고, Original은 두 분석에서 재사용한다. 추가 분석 2의 길이 제약 문맥은 별도로 준비한다.
- 미확정: 추가 분석 2의 목표 보존율·허용오차·추출 조합 세부는 이후 정한다. 추가 분석 코드는 이번 변경에서 구현하지 않는다.
- 메인 영향: 실행 코드·프롬프트·config는 변경하지 않는다. 검토용으로 제안했던 faithful 교체와 선별 문장 추가안도 메인에 적용하지 않는다. 기존 Dev를 재실행하거나 실행 중인 메인 결과를 변경하지 않는다.
- 검증: 설계서·README의 질문 조건과 호출 수 계산을 대조하고 메인 코드·설정의 해시가 변경 전후 같은지 확인한다.

## D012 · 2026-11-14 · Qwen3 실제 디코딩 오류 수정과 검증된 압축 재사용

- 발견: Test Original 시작 로그에 `do_sample=True` 등 모델 기본값으로 변경했다는 경고가 표시됐다. 코드에는 greedy 요청이 있었지만, [Transformers 4.57.1의 설정 병합](https://github.com/huggingface/transformers/blob/v4.57.1/src/transformers/generation/utils.py)에서 전역 기본값과 같은 필드를 모델 기본값으로 대체했다. 사전 기록한 `generation_config`만 보고 실제 동작을 잘못 판단했다.
- 실제 영향: 캐시된 고정 모델 설정과 사용자 환경의 CPU 설정 병합으로 Qwen3의 실제 `do_sample=True`를 재현했다. 기존 Dev/Test 판단은 의도한 greedy 조건을 만족하지 않는다. `torch_dtype` 명칭 경고는 별개다. 기존 Dev 정확도로 설정을 고른 것은 아니다.
- 압축 확인: Qwen2.5 모델 설정의 저장 버전은 4.37.0, Qwen3는 4.51.0이었다. 같은 라이브러리에서도 기본값 상속 분기가 달랐다. Qwen2.5의 기존 실제 디코딩은 greedy였으며 수정 후와 전체 적용 설정이 동일했다. 압축 관측과 토큰 보존율은 폐기할 이유가 없다.
- 수정: 기본값 상속을 명시적으로 끄고 생성 호출에도 `do_sample=False`, `num_beams=1`, `use_cache=True`를 전달한다. 추론 전에 실제 병합 설정을 확인하며 적용된 설정과 호출 인자를 기록한다. 프롬프트·모델·정밀도·길이 상한은 바꾸지 않는다.
- 복구 결정: 원본 run·protocol·판단 로그는 보존한다. 새 전체 Dev run에 동등성이 입증된 압축 결과만 복사하고 모든 판단을 greedy로 다시 실행한다. 이어 새 protocol과 Test를 만든다. 샘플링 판단과 greedy 판단을 섞거나 이전 run의 해시를 수정하지 않는다. 잘못된 Test 실행은 구현 오류로 중단한 것으로 기록한다.
- 범위 제한: `reuse-compression`은 알려진 D012 이전 소스 해시, 불변 스냅샷, 동일한 전체 Dev·프롬프트·고정 모델·환경을 검사한다. 캐시된 설정으로 기존과 수정 후의 실제 압축 디코딩을 비교하고 원문·출력 토큰·프롬프트 해시·추출 조합·최종 길이를 검증한다. 샘플링 압축이나 다른 설정은 거부한다. 성공·실패·상한 도달을 포함한 압축 결과 전체를 가져오며 이전 판단은 0건 가져온다.
- 출처와 시간: `compression_reuse.json`에 출처와 검사 결과를 기록한다. 원래 압축 소요시간을 유지하며 새로 실행한 시간인 것처럼 표현하지 않는다. 이전 Dev 판단 시간·종료·파싱 관측은 샘플링 결과로 정정한다.
- 검증: 실제 Transformers 설정 병합 CPU 검사, 생산 `generate` 호출의 명시 인자 검사, 샘플링 압축 재사용 거부, 복사 전후 판단 격리·원본 비변경 검사. 실제 기존 Dev의 244개 압축 출력 모두 CPU/토크나이저 검증을 통과했다. 모델 가중치 로드·GPU 추론·Dev/Test 재실행은 하지 않았다.
- 한계: 이전 표준 라이브러리 stub 검사만으로는 Transformers 내부 설정 병합을 잡지 못했다. 의존성 설치 후 실제 라이브러리 설정 회귀 검사도 실행한다. 수정된 모델의 실제 추론 검증은 로컬 Dev에서 수행한다.
