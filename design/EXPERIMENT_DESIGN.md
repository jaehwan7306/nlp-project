# 계약서 문맥 압축 실험 설계

작성일: 2026-11-12

최종 수정일: 2026-11-15

상태: 메인 5조건과 Q17을 완료했다. 추가 분석 1의 Q8 후속 실험은 별도 실행 파일로 구현했다. 동일 보존율 실험은 보류하고 길이 차이를 해석의 한계로 기록한다. Gold Evidence 기반 오류 분석은 후속 범위다.

**이번 작업의 범위**

Main을 새로 구성할 때 이전 실험의 압축문, 예측, 성능 수치, 전처리 검토 결과, 제외 ID 목록을 재사용하지 않는다. 공식 데이터부터 다시 점검하고 Original도 새로 평가한다. 추가 분석 1에서는 이렇게 완료한 현재 Main을 비교 기준으로 사용하고 Original을 재사용한다. 기존 실행 폴더와 결과를 덮어쓰지 않는다.

코드는 사용자의 작성 요청에 따라 새로 구성했다. 모델 다운로드·로딩·Dev/Test 실험은 사용자가 로컬에서 진행한다. 에이전트의 검증은 작은 CPU 테스트, 구문·입출력·CLI 점검 등으로 제한한다.

**연구 목적**

질문을 미리 알려주면 계약 판단에 필요한 정보를 더 잘 보존할 수 있는지 확인한다. 질문 없는 압축의 기본 성능을 먼저 비교하고, 질문 제공량을 바꾼 실험과 Gold Evidence 기반 오류 분석으로 이어간다.

추가 분석 1에서는 ContractNLI의 고정 17개 가설 중 압축기에 제공하는 개수를 0, 8, 17로 비교한다. 문서·방법별로 목록을 한 번 제공해 만든 문맥을 가설 17개 판단에 사용한다.

**데이터와 모델**

| 항목 | 원칙 |
|---|---|
| 데이터 | ContractNLI 공식 Train/Dev/Test 분할 |
| Train | 학습과 모델 추론에 사용하지 않고 교차 중복 점검에만 사용 |
| Dev | 전처리·출력 형식·파싱·실행 가능성 등 기술 점검에 사용 |
| Test | 새 전처리 목록과 확정한 메인 규칙으로 평가 |
| 압축·선택 모델 | Qwen2.5-7B-Instruct, 네 압축 조건이 같은 모델과 정밀도 사용 |
| 판단 모델 | Qwen3-8B, thinking off, 전 조건 같은 판단 설정 |
| 정밀도 | 두 모델의 4bit 공통 설정을 고정하고 실제 설정 기록 |
| 디코딩 | Greedy. 모델 기본값 상속을 끄고 매 생성 호출에 명시하며 실제 적용 설정을 검증·기록 |
| 학습 | 별도 학습·미세조정 없음 |

긴 입력의 SDPA 메모리 부족에는 전체 토큰과 모델 설정을 유지하는 head별 계산 확장을 사용한다(D013). 최종 실행은 D014에 따라 Original 포함 Test의 모든 압축·판단을 이 고정 정책으로 처음부터 생성한다. 이전 Test 예측·압축 결과를 섞지 않는다. 먼저 최장 Dev 원문 1문서의 압축 4회·판단 5회에서 동일 입력·형식·greedy·정책의 기술 점검을 하며, 이전 출력과의 일치는 참고로 기록한다. 기본 Dev 동결 파일은 보존하고 새 보완 소스·해시·기술 점검을 포함한 별도 protocol과 Test를 만든다. 짧고 긴 입력이 같은 분기 규칙을 따르는 것이며 모든 호출의 연산량·커널·시간이 같다는 뜻은 아니다. 실행 명령은 README의 전체 Test 재실행 절차를 따른다.

공식 데이터는 Train 423, Dev 61, Test 123문서와 고정 17개 가설로 구성된다. 실제 평가 문서 수는 새 검토와 제외 목록에서 계산하며 이전 실험의 최종 수를 가져오지 않는다.

참고: https://stanfordnlp.github.io/contract-nli/

**새 전처리**

1. 공식 원본 파일을 확보하고 파일 해시·획득 정보를 기록한다. 원본 계약서, 라벨, Gold Evidence의 문자 위치는 보존한다.
2. 문서 ID, 가설 목록, 17개 라벨, 허용 라벨 값, 원문과 span 범위, 근거 인덱스 등을 검사한다. 데이터 문제를 자동으로 덮어쓰지 않고 기록한다.
3. 중복 탐지용 정규화 사본을 별도로 만든다. 정규화 규칙을 기록하며, 이를 모델 입력 원문으로 자동 대체하지 않는다.
4. 원문 완전 중복, 정규화 중복, 유사 중복 후보를 새로 생성한다. 유사도 방식과 후보 임계값은 구현 명세에 기록하고, 유사도만으로 자동 제외하지 않는다.
5. 사람이 원문·라벨·근거를 검토하고 최종 처리 방식을 CSV에 직접 기록한다. `duplicate`는 Test 우선·같은 split에서 작은 ID 하나 유지, `exclude_both`는 해당 두 문서 모두 제외, `distinct`는 이 쌍을 이유로 추가 제외하지 않음이다. 동일 내용의 라벨 충돌로 둘 다 제외하기로 결정했다면 사람이 `exclude_both`를 선택한다. 코드가 라벨 차이로 처리 방식을 바꾸거나 임의 재라벨링하지 않는다.
6. Evidence 위치나 표현의 차이는 라벨 충돌과 구분해 기록한다. Dev/Test 교차 중복에서 `duplicate`를 선택하면 Test를 유지하고 Dev 개발 대상에서 제외한다. Train과의 중복은 별도로 보고한다.
7. 최종 제외 목록에 ID, 관련 ID, 처리 유형, 사유와 검토 내용을 기록한다. 공식 파일을 수정하는 대신 실행 대상 목록으로 적용한다.

이 목록과 최종 평가 문서 수는 실제 데이터 점검 이후 확정할 산출물이다. 과거 제외 목록으로 미리 채우지 않는다.

**추출 단위**

공식 문서의 전체 `spans`를 우선적인 선택 단위로 검토한다. 각 span은 원문의 문장 또는 목록 항목에 해당하는 문자 위치 정보다. 새 데이터에서 범위가 유효한지, 분할로 원문 내용이 빠지는지, 비정상적으로 분리된 구간이 있는지 검사한 뒤 사용 규칙을 확정한다. 필요한 보완이 있으면 일관된 규칙과 원문 위치 대응을 기록한다.

문서의 전체 span 목록과 가설별 Gold Evidence 목록은 구분한다. 압축에는 모든 후보 단위의 ID·본문만 제공하고, 어느 단위가 Gold Evidence인지는 제공하지 않는다. 모든 압축 조건에는 동일한 번호가 붙은 원문을 제공한다.

ID는 원문 단위의 식별자이며 중요도 등수가 아니다. 모델에는 선택한 ID 목록을 반환하도록 하고 중요도순 반환은 요구하지 않는다. 최종 추출 문맥은 원문 위치 순으로 정렬해 병합한다. 선택 단위 내부는 자르거나 다시 쓰지 않는다.

**메인 실험: Original과 압축 4조건**

| 조건 | 출력 방식 | 보존 우선순위 지시 | 압축 시 질문 |
|---|---|---|---|
| Original | 원문 그대로 | 해당 없음 | 해당 없음 |
| 생성형·일반(Naive) | 축약 본문 작성 | 없음 | 없음 |
| 생성형·보존 우선(Contextualized) | 축약 본문 작성 | 있음 | 없음 |
| 추출형·일반 | 원문 단위 ID 선택 | 없음 | 없음 |
| 추출형·보존 우선 | 원문 단위 ID 선택 | 있음 | 없음 |

보존 우선순위는 의무 주체, 조건, 예외, 부정·금지, 논리 연결, 적용 범위다. 두 보존 우선 조건에 같은 문장을 사용한다. 같은 압축 방식 안에서는 이 문장 하나만 다르게 하고 나머지 지시와 설정은 유지한다.

공통 지시는 원문을 데이터로 취급하고, 원문에 없는 내용을 추가하지 않으며, 사실적 의미를 보존하도록 한다. 프롬프트 전문은 contract_experiment/prompts.py에서 확인하며, Dev 기술 점검 후 Test 전에 동결한다.

메인에서는 출력 분량을 지정하는 추가 지시를 사용하지 않는다. 목표 토큰 수·보존율·문장 수·선택 개수·남은 예산 등을 프롬프트에 넣지 않는다. 최소 길이 강제, 목표 길이에 맞춘 재작성·후보 선택·추가 생성도 하지 않는다.

실행을 위한 안전 상한과 정지 문자열은 Dev에서 기술적으로 점검한다. 안전 상한은 목표 보존율이 아니며 도달 여부를 기록한다. 상한 도달만으로 의미적 미완성을 확정하지 않는다.

판단 모델에는 모든 조건에서 같은 형식으로 문맥과 가설을 제공한다. 압축 모델에 가설을 숨기는 것과 판단 모델에 가설을 제공하는 것은 별개의 단계다.

**메인의 출력 처리 방향**

| 상황 | 합의한 추천 방향 |
|---|---|
| 유효한 선택 ID 목록 | 원문 위치 순서로 정렬해 원문 단위를 병합 |
| 중복 ID | 한 번만 사용하고 중복 발생 기록 |
| 정상적인 빈 목록 `[]` | 빈 선택으로 기록하고 빈 문맥으로 판단 |
| 존재하지 않는 ID 또는 해석 불가능한 형식 | 압축 실패로 기록. 원문 대체·자동 재생성하지 않음 |
| 판단 라벨 추출 실패 | 원본 보존, 오답 처리, 실패율 보고 |

허용할 JSON 포장 형식, 압축 실패 행의 구체적인 집계 표현 등 구현 세부는 메인 Dev 전에 명시하고 Test 전에 고정한다. 실패 행을 조용히 제거하지 않는다.

**추가 분석 1: 질문 제공 효과**

네 압축 방법 각각에서 다음 입력 조건을 비교한다.

| 질문 조건 | 압축 모델 입력 | 압축 및 판단 방식 |
|---|---|---|
| 질문 없음 | 계약서만 제공 | 메인의 문서·방법별 압축 문맥과 판단 결과 재사용 |
| 8개 가설 목록 제공 | 계약서 + 문서별로 균형 있게 배정한 가설 8개 | 문서·방법별 한 번 압축하고 그 문맥으로 17개 가설을 각각 판단 |
| 17개 가설 목록 제공 | 계약서 + 공식 17개 가설 전체 | 완료한 Q17의 문서·방법별 압축 문맥과 판단 결과 재사용 |

문서당 한 번은 각 압축 방법 안에서 한 번이라는 뜻이다. 네 방법은 각각 독립된 압축 문맥을 하나씩 만든다. 개별 가설마다 재압축하지 않는다.

기본 작업 지시·보존 우선 문장·모델·정밀도·디코딩·출력 형식은 메인과 동일하게 유지한다. 질문 제공 조건에는 가설 목록과 이 목록이 검증할 주장이라는 공통 안내를 추가한다. 가설을 참이라고 가정하거나, 가설에만 있는 내용을 계약서 사실로 추가하거나, 가설별 정답을 출력하도록 요구하지 않는다. Gold Label과 Gold Evidence는 압축 모델에 제공하지 않는다.

Q17은 모든 문서에 공식 목록을 제공한다. Q8은 Q17 프롬프트에서 미제공 가설 줄을 제거하며 남은 가설의 H 번호와 상대적 순서를 유지한다. 같은 문서의 네 방법에는 같은 목록을 넣는다. 출력은 생성형이면 요약문 하나, 추출형이면 선택 ID 목록 하나다.

판단 모델에는 해당 방법의 압축 문맥과 현재 판단할 가설 한 개를 기존 형식으로 제공한다. 같은 문맥을 17개 가설에 재사용하며, 판단 프롬프트에 17개 목록을 추가하지 않는다. Original은 메인 결과를 재사용한다.

길이 목표는 제공하지 않는다. 질문 제공으로 출력 길이가 달라질 수 있으므로 성능과 실제 보존율·비용을 함께 보고한다. 결론은 **평가할 가설 목록을 미리 알려준 효과**로 한정한다.

평가 문서가 N개이면 Q8의 새 압축 호출은 4N회, 새 판단 기록은 4 × 17N건이다. Original 17N건을 복사하고 완료한 Q0·Q17의 네 압축 조건을 참조한다.

**실행 구현(2026-11-15).** 완료한 `runs/test_memory_safe`와 같은 코드·데이터·제외 목록·환경·실제 runtime을 검증한다. `run_question_analysis.py`는 Main 소스 및 메모리 보완 소스를 수정하지 않는 별도 진입점이다. 가장 긴 Q17 Dev 입력부터 소규모 기술 점검을 수행하며 정확도는 계산하지 않는다. 통과 후 Q17 프롬프트 전문·목록 순서·모든 실행 소스·실제 모델 설정과 참조 Main 해시를 별도 동결한 Test를 생성한다.

Original 문맥·예측은 그대로 복사하며 질문 없는 네 압축 조건은 참조 비교한다. 새 판단은 네 압축 조건에 대해서만 수행한다. 저장 건수 85N에는 재사용 Original 17N이 포함되고, 새 판단 목표는 68N이다. 실패는 Main과 동일하게 오답·기록 처리하므로 실패 문서에서 실제 모델 판단 호출은 생략될 수 있다. 결과는 Main과 분리하고 중단 시 완료한 성공·실패 기록을 유지해 재개한다.

방법별 Q17−Q0 Accuracy·Macro-F1과 같은 문서 표본을 사용하는 paired 문서 부트스트랩 percentile 95% CI를 보고한다. Main의 10,000회·seed 42를 유지하고 Macro-F1을 매 반복 다시 계산한다. 실제 보존율, 압축·파싱 실패, 클래스 Recall·라벨 수, 정답 전환과 추가 시간을 함께 제시한다. 형식 실패 변화와 출력 길이 변화가 성능 차이에 기여할 수 있으므로, 이를 근거 내용 보존만의 효과나 길이를 제거한 효과로 해석하지 않는다. CI는 다중 비교 보정 없는 탐색적 비교다.

**Q8 배정과 비교(2026-11-19).** seed 42로 문서 순서를 섞고, 17문서씩 나눈 블록마다 가설 순서를 섞어 순환 목록에서 문서당 8개를 배정한다. 균형 기준은 가설별 제공 횟수다. 119문서에서 각 가설은 56문서에 제공되고 63문서에서 빠진다. 배정에는 문서·가설 ID만 사용하며 `assignment.json`에 모델 실행 전 동결한다. 원문, 근거 span, 평가용 가설·Gold는 모두 같은 Test 스냅샷을 사용한다.

주 비교의 분모는 방법당 119 × 17 = 2,023문항이다. Q8−Q0와 Q8−Q17을 같은 문서·가설에서 계산한다. 보조 분석에서는 Q8의 제공 여부를 세 조건에 공통으로 붙여 제공 952문항, 미제공 1,071문항 각각에서 같은 차이를 본다. 가설별 결과도 기록한다. Accuracy·Macro-F1의 문서 단위 paired bootstrap 95% CI는 10,000회, seed 42이며, Q8 배정표는 고정한다. 관측된 차이에는 함께 제공된 가설의 조합, 길이, 형식 실패의 영향이 함께 반영될 수 있다.

**동일 보존율 실험 보류.** 현 단계에서는 공통 토큰 예산을 강제하는 추가 분석 2를 보류한다. 결과에 실제 보존율을 함께 보고하며, 자연 출력이 길어진 효과와 압축 방식·질문 제공 효과가 섞일 수 있음을 한계에 기록한다.

**추가 분석 3: Gold Evidence 기반 오류 분석**

Q0·Q8·Q17의 개선·악화·지속 오답 사례를 원문 근거와 대조한다. 문서·방법별 공유 압축 문맥을 각 가설의 Gold Evidence와 비교하며, 오류 분석을 위해 가설별로 다시 압축하지 않는다. 근거 누락, 주체·조건·예외·부정 등의 의미 변경, 원문에 없는 내용, 출력 잘림, 판단 오류 후보를 살펴본다.

단어 일치와 의미 보존을 구분한다. 근거 누락만으로 길이 상한이 원인이라고 단정하지 않고 종료 상태·문장·선택 로그를 함께 확인한다. NotMentioned는 Gold Evidence가 없으므로 근거 보존율 분모에 넣지 않는다.

기본은 오류 사례 분석이다. 의미적 보존율이나 오류율을 수치화하려면 검토 표본과 판정 기준을 별도로 정하고 검토 범위에 맞게 해석한다. 사람 검토를 메인 실행의 필수 게이트로 만들지 않는다.

Lost in the Middle 및 중요도순 재배열 분석은 포함하지 않는다.
