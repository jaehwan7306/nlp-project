# 추가 분석 1: 17개 가설 목록 제공 결과

[공개 결과 목록](../README.md) · [실험 결과 요약](../../docs/RESULTS.md)

분석일: 2026-11-16. Q0는 완료한 질문 없는 Main, Q17은 같은 계약서와 압축 방법에 고정 17개 가설 목록을 함께 제공한 실행이다. 실제 모델 추론을 추가로 실행하지 않고 저장된 결과를 분석했다. 원본 실험 파일은 수정하지 않았다.

**핵심 판단**

Naive의 정확도는 61.05%에서 63.67%로 2.62%p 올랐다. 그러나 질문 제공이 모든 방법을 개선하지는 않았다. 보존 우선 요약은 뚜렷한 개선을 보이지 않았고, 추출형은 남긴 분량이 크게 줄면서 정확도가 내려갔다. 특히 Q17의 생성형 출력이 원문 단위 번호와 본문을 많이 남기는 방식으로 변한 점이 중요하다. 관측한 이득은 출력 방식·길이·형식 준수 변화를 포함한 질문 목록 제공의 전체 효과다.

**결과의 완결성과 변인 확인**

119문서 × 17가설 = 2,023문항이다. 새 압축 476회와 새 판단 8,092건이 완료됐고, Original 2,023건은 Main과 완전히 같은 기록으로 재사용했다. 저장된 595개 문맥과 10,115개 판단의 키·Gold·문서가 일치하며 최신 진단 해시도 일치한다. Q17 loader의 실제 동결 소스·runtime·Main 참조 검사도 통과했다.
캐시된 토크나이저만 사용해 test:1·90·336·455의 네 방법, 총 16개 실제 입력을 재구성했고 저장된 rendered prompt SHA256과 모두 일치했다. 생성형에 원래의 요약 지시와 “without ... source unit IDs”가 포함돼 있었다. 코드가 추출형 작업을 잘못 호출했다는 근거는 없으며, 이후의 번호 보존은 모델 출력의 관측이다. 모델 가중치 로드나 GPU 추론은 수행하지 않았다.

Original은 63.72% (1289/2,023), Macro-F1 0.5255다. Q17 Naive는 Original보다 정답이 한 개 적지만, 같은 문항을 모두 보존한 것은 아니다. Original 정답 1,289개 중 146개를 놓치고 Original 오답 중 145개를 새로 맞혔다. Original 정답 유지율은 88.67%다. 가까운 정확도를 전체 판단의 동일성·비열등성으로 해석하지 않는다.

문서 단위 paired bootstrap 10,000회, seed 42, percentile 95% CI이며 17문항을 함께 추출하고 Macro-F1을 매 반복 재계산한 사전 구현 결과를 사용했다. Naive 정확도 차이 CI는 [0.59, 4.75]%p, Macro-F1 차이 CI는 [0.0086, 0.0619]로 0을 포함하지 않는다. 추출형·보존 우선의 정확도 차이 CI도 음수지만 Macro-F1 차이 CI는 0을 포함한다. 나머지 정확도 차이는 0을 포함해 방향을 확정하기 어렵다. 여러 비교를 보정하지 않았으므로 모두 탐색적 해석이다.

보존율은 판단에 실제 사용한 문맥의 Qwen3 토큰 수 / 원문 토큰 수다. 아래 평균은 문서별 보존율의 산술평균이며 전체 토큰 합의 비율과 구분한다.

|---|---:|---:|---:|---:|---:|
| 생성형·일반 (Naive) | 62.77% | 62.51% | 66.26% | 61.23% | 119/119 |

Naive는 평균 길이가 늘지 않은 상태에서 성능이 올랐다. 다만 119문서 중 107문서는 두 실행의 보존율 차이가 5%p보다 컸다. 따라서 평균 일치만으로 문서별 길이가 통제됐거나 길이와 무관한 효과라고 주장할 수 없다. 추출형·일반은 평균 약 35.44%p, 보존 우선은 약 27.54%p 적게 남겼다. 질문 목록이 선택을 더 좁히는 방향으로 작동했을 가능성이 있지만, 실제 중요도 선택의 개선인지 필요한 근거의 삭제인지는 근거 대조가 필요하다.

- Original의 Contradiction Recall도 18.06%이고 Q17 최선인 Naive도 25.00%다. 모순 판단은 압축 전부터 약한 영역이며 압축 성능만으로 전체 오답을 설명할 수 없다.

**중요한 출력 방식 변화**

| 조건 | 줄 시작 [숫자] 표시 Q0/Q17 | Q17에서 같은 ID의 원문 단위 완전 일치가 확인된 문서 | 확인된 원문 단위가 출력 문자의 80% 이상인 Q17 문서 |
|---|---:|---:|---:|
| 생성형·일반 (Naive) | 1/111 | 104/119 | 19/119 |
| 생성형·보존 우선 (Contextualized) | 1/101 | 89/119 | 11/119 |

이 지표는 사후 형식 점검이다. 줄 시작 [정수] 뒤의 본문을 해당 원문 단위와 공백 정규화 후 정확히 대조했다. 80%는 설명용 사후 기준이며 의미적 충실도·Gold Evidence 보존율이 아니다. 번호 없이 복사한 텍스트는 잡지 못하므로 일반적인 전체 복사율이나 Q0/Q17의 공정한 복사 성능 지표로 쓰지 않는다.

실제 test:1의 생성형·보존 우선 Q17은 118개 번호 표시 중 117개 단위의 본문이 원문과 완전히 일치했다. 확인한 원문 단위가 번호를 뺀 출력 문자의 약 95.5%였다. Q0는 번호 없이 요약한 본문이었다. 따라서 Q17 생성형 출력을 모두 새로 재서술한 요약으로 간주하면 해석이 틀릴 수 있다. 질문 제공은 무엇을 남기는지와 함께 어떻게 출력하는지도 바꿨다. 번호 포함은 원래 지시 위반이며, 그 번호가 실제 판단 문맥과 토큰 수에 남아 평가됐다는 점도 기록한다. 현재 결과에서 사후 제거하거나 재판단하지 않았다.

**형식 실패와 출력 이상**

Q17 압축 실패 0건, 판단 파싱 실패 0건이고 모든 판단은 eos로 종료했다. 이 사실은 본문의 의미적 정확성이나 모든 압축의 자연 종료를 뜻하지 않는다.

- 생성형·일반 상한 도달: test:58·227·591, 3/119건. 생성형·보존 우선: test:58·227·521, 3/119건. 일부 출력은 원문 단위 번호·본문을 길게 남기다가 중간 문장으로 끝났다. 목표 길이를 준 것은 아니지만 기존 4,096 생성 토큰 안전 상한은 실제로 작동했다.
- 추출형 두 방법 모두 test:90·336·455에서 정상 JSON `[]`를 반환해 빈 문맥이 됐다. 재파싱 실패가 아니라 선택 결과이며 메인 정책대로 51문항씩 그대로 평가했다. 이 세 문서는 Gold 기준으로 Entailment 7개와 Contradiction 1개도 포함하므로 전체가 무관한 자료라고 단정할 수 없다.
- 추출형·일반 test:21에서 중복 ID가 있어 기존 규칙대로 한 번만 조합했다. Q0 추출형·일반 test:1의 기존 압축 실패 17문항도 비교 분모에 유지했다.
- Naive Q17에는 보존율 100% 초과가 13문서, 생성형·보존 우선에는 5문서 있었다. 원문보다 긴 출력도 있으므로 항상 압축에 성공했다고 쓰지 않는다. 길이 초과만으로 없는 사실 추가를 단정하지 않는다.

상한·빈 문맥·기존 압축 실패가 있는 문서를 양쪽에서 공통 제외해 보는 사후 점검에서도 방향은 같았다. 이는 주 결과를 대체하지 않으며 새로 정한 부분집합의 기술 통계다.

**보고에 사용할 해석과 다음 단계**

“고정 17개 가설 목록을 압축 단계에 제공했을 때 일반 생성형 조건의 정확도는 2.62%p 개선됐지만 다른 방법에서 일관된 개선은 관측되지 않았다. 추출형에서는 출력 길이와 Entailment Recall이 함께 감소했다. 질문 목록 제공은 길이뿐 아니라 생성형의 번호 포함·원문 단위 보존 등 출력 방식도 바꿨다. 따라서 이 결과는 자연 출력에서의 질문 목록 제공 효과이며, 동일 길이에서 질문의 관련 정보 선택 능력만 분리한 결과는 아니다.”

현재 결과를 보존하고 출력 문제·사후 진단을 함께 보고하는 것이 타당하다. 같은 길이 비교는 계획한 추가 분석 2에서 다루고, nda-3 등 변화가 큰 가설과 빈 선택·상한 사례는 추가 분석 3의 근거 대조 후보로 삼을 수 있다. 생성형에서 번호 제거를 더 강하게 지시하는 후속 실험을 한다면 두 질문 조건에 공통 적용한 새 프로토콜로 구분해야 하며 현재 Q17만 유리한 출력으로 교체하지 않는다.
